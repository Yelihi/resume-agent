# 로컬 원본 파일 회귀 검증

원본 PDF/DOCX와 정답 파일은 저장소 밖에 둔다. 개인정보가 포함된 추출문을 CI 로그나 Git에 추가하지 않는다.
일반 테스트는 합성 문서와 가짜 OCR 엔진으로 실행하고, 실제 파일 검증은 아래 명령으로 명시적으로 실행한다.
실제 검증은 설치된 로컬 PaddleOCR를 사용한다. 첫 실행에는 모델 다운로드가 필요할 수 있으며 OpenAI API는 호출하지 않는다.

## 정답 준비

문서 화면을 사람이 읽고 핵심 문장을 선정한다. 추출 결과를 그대로 정답으로 복사하면 같은 오류가 정답에도 들어간다.
페이지마다 제목·본문·수치/단위·영문 기술명을 포함하고, 여러 단 문서는 각 단에서 선정한다.
PDF/이미지는 실제 페이지 번호, DOCX/TXT는 현재 추출 모델상 한 페이지(`page: 1`)로 지정한다.

저장소 밖에 `expected.json`을 만든다:

```json
{
  "pageCount": 1,
  "anchors": [
    { "page": 1, "text": "사람이 원본을 보고 확인한 핵심 문장" },
    { "page": 1, "text": "100ms" }
  ]
}
```

## 실행

프로젝트의 `backend` 디렉터리에서:

```bash
uv run python -m scripts.check_extraction "/절대경로/원본.pdf" "/절대경로/expected.json"
uv run pytest tests/document_processing tests/review -q
```

성공은 종료 코드 0, 누락/불일치는 1, 추출 자체가 실패하면 오류로 종료된다.
스크립트는 원문 대신 실행 시간과 실패한 앵커 번호/페이지를 출력한다.
한글 NFC 및 공백만 정규화해 비교하며 숫자·문장부호·대소문자는 그대로 검사한다.
이는 중요 구간의 재현 검사이지 문서 전체 정확도 검증은 아니다. 본문 전체를 전사한 표본에는
기존 `benchmarks.ocr.metrics.character_error_rate`로 문자 오류율을 추가 측정할 수 있다.

## 단계별 확인

1. 추출: 페이지 수, 핵심 문장, 숫자와 단위, 누락, OCR 사용 여부를 확인한다.
2. 위치: 원문 화면에서 제안의 하이라이트가 같은 문장을 가리키는지 확인한다.
3. AI: 추출이 통과한 후 별도 검토를 실행해 인용 실패를 확인한다. AI 실행은 비용과 비결정성이 있으므로 추출 회귀 검사에 섞지 않는다.
4. 앱: 기존 IndexedDB 검토 결과는 자동 재추출되지 않는다. 수정 코드를 확인할 때 원본을 다시 업로드하고 새 검토 결과인지 확인한다.

## 깨진 대체 텍스트 회귀 사례

화면은 정상인데 PDF의 `ActualText`가 손상된 경우가 있다. 현재 파이프라인은 기본 추출에서
깨짐을 감지하면 `TEXT_IGNORE_ACTUALTEXT`로 표시 문자를 다시 추출하고, 그것도 깨져 있으면 OCR로 전환한다.
대체 텍스트는 정상 문서에서 의미가 있으므로 모든 PDF에서 무조건 무시하지 않는다.
개인 원본 대신 같은 구조의 합성 PDF를 `test_corrupted_actual_text_uses_visible_glyphs_before_ocr`에서
메모리 내 생성해 검사한다. 기본 추출은 실패하고 개선된 추출은 OCR 없이 정상 문장을 얻어야 한다.
