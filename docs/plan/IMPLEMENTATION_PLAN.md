# Resume Review Harness — Implementation Plan

세부 이슈는 각 단계의 범위와 통과 조건을 확정한 뒤 작성한다. 앞 단계가 통과하기 전에는 다음 단계 기능을 섞지 않는다.

## 1차 검증 — 문서 정규화 모델

상태: 완료

목표: AI와 UI 없이 입력 문서를 신뢰 가능한 `PageDocument` 또는 `FlowDocument`로 변환한다.

범위:

- FastAPI 백엔드 최소 실행 환경
- PDF, 이미지, DOCX, TXT와 직접 입력 텍스트의 형식 검증 및 추출
- `lineId`, bbox 또는 UTF-16 offset을 포함한 고정 DTO
- OCR 후보 설치·품질 벤치마크 후 런타임 엔진 하나 선택
- 예상 가능한 입력 오류의 안전한 응답과 내부 로그
- pytest 기반 계약·추출 테스트

통과 조건:

- 준비한 형식별 표본이 정해진 DTO 스키마를 통과한다.
- 모든 줄 식별자가 문서 안에서 유일하고 원문 위치로 다시 연결된다.
- OCR 엔진 선택 근거와 측정 결과가 남아 있다.
- 손상·위장·빈 입력과 제한 초과 입력이 AI 호출 전에 거부된다.

## 2차 검증 — 검토 실행 모델

상태: 완료

목표: UI 없이 정규화된 이력서와 선택 자료를 받아 최종 `{ status, errors, materialReviews, results }`를 생성한다.

범위:

- 기본 이력서 원칙과 `spellCheck`, 조건부 회사 자료·공고 분석, `finalReview`
- OpenAI Responses API와 Structured Outputs
- 애플리케이션 오케스트레이터의 병렬 실행, 오류 취합과 최종 상태 계산
- 유효한 `lineIds`와 `quote`만 남기는 후처리
- 부분 실패, 특정 모듈 재실행, 최종 검토 재실행과 취소
- 고정 가짜 AI 응답을 사용하는 자동 테스트와 별도 실제 모델 평가

통과 조건:

- 성공·부분 실패·전체 실패·취소 시나리오가 동일한 최종 계약으로 반환된다.
- 모델 출력이 원문에 없는 위치나 사실을 참조하면 결과에서 제거되거나 실패 처리된다.
- 일부 자료나 모듈이 실패해도 가능한 범위에서 검토가 완료된다.
- 실제 모델 평가 표본이 합의한 품질 불변 조건을 통과한다.

## 3차 검증 — 로컬 웹 사용자 흐름

상태: 완료

목표: React 화면에서 입력부터 결과 확인까지 전체 흐름을 사용할 수 있게 한다.

범위:

- 이력서 하나와 회사 자료·공고 여러 개의 입력 UI
- 원본 및 파생 데이터의 IndexedDB 임시 보관·교체·삭제
- PDF.js 및 문서 유형별 뷰어와 `lineId` 기반 수정 위치 표시
- `이력서 검토하기`, 고정 SSE 진행 안내와 검토 취소
- 검토 중 입력 비활성화, 오류·경고·수정 제안 UI
- 직전 검토 결과와 사용자 의견을 다음 검토의 참고 입력으로 전달

통과 조건:

- 새 이력서 교체 시 이전 원본·파생 데이터와 화면 결과가 합의한 순서로 정리된다.
- 회사 자료는 이력서 교체 후에도 유지되고 명시적 삭제 시에만 사라진다.
- 수정 제안을 선택하면 원문에서 대응 위치를 찾을 수 있다.
- 새로고침·취소·부분 실패에서도 사용자에게 거짓 완료 상태를 보여주지 않는다.

## 3차 이후 — 저장 계약과 문서 동기화

상태: 완료 (2026-09-10)

- 검토출처·검토자료근거·자료별 반영 여부를 현재 응답 계약에 반영한다.
- 입력·완료 모듈·최종 응답을 `ReviewRecord`로 IndexedDB에 저장한다.
- 저장된 기록으로 서버 재시작 후에도 결과 조회·모듈 재실행이 가능하다.
- 저장 성공 뒤 서버 기록을 해제하고 저장 실패 시 서버 결과와 실행 ID를 유지한다.
- 다음 작업: IndexedDB 24시간 자동 삭제. 아직 구현하지 않았다.

## 이후 판단

3차 검증이 끝난 뒤에만 공개 웹과 Electron 중 확장 방향, 서버 데이터베이스, GlitchTip, Docker와 추가 분석 모듈을 결정한다.
