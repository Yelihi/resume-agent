# Phase 2 Test Cases

## P2-01 계약·후처리

- [x] 여섯 필드 이외의 수정 제안 속성을 거부한다.
- [x] `수정성격`은 합의한 여덟 값만 허용한다.
- [x] 존재하지 않거나 중복되거나 빈 `lineIds` 제안을 제외하고 `INVALID_LOCATION`을 만든다.
- [x] 줄을 순서대로 합친 문자열에 정규화한 `quote`가 없으면 `INVALID_QUOTE`로 제외한다.
- [x] 일부 제안만 탈락하면 유효 제안과 `partial`을 반환한다.
- [x] 모델이 처음부터 빈 배열을 반환하면 `success`, 생성 제안이 모두 탈락하면 `failed`다.

## P2-02 비-AI 맞춤법

- [x] 반복 공백과 문장부호 앞 공백을 해당 줄 위치와 함께 찾는다.
- [x] 확실하지 않은 한국어 어휘·문법을 추측하지 않는다.
- [x] 문제가 없으면 빈 진단을 성공 출력으로 반환한다.

## P2-03 참고 자료

- [x] 직접 텍스트·정규화 문서·URL 자료를 명확히 구분한다.
- [x] 빈 내용, 잘못된 URL, 중복 자료 식별자를 거부한다.
- [x] 회사 자료와 채용 공고 종류를 구분한다.

## P2-04 OpenAI 경계

- [x] 최종 호출은 원본 파일 없이 정규화 문서와 고정 원칙을 전달한다.
- [x] Structured Outputs의 루트는 `{ materialReviews, results }`이며 `store=false`다.
- [x] URL이 있을 때만 `web_search`를 추가하고 도구 사용을 필수로 한다.
- [x] 입력 URL이 출처에 없으면 해당 분석을 실패 처리한다.
- [x] SDK·스키마 실패를 안전한 모듈 오류로 변환한다.

## P2-05 오케스트레이션

- [x] 선택 자료가 없으면 맞춤법과 최종 검토만 실행한다.
- [x] 공백 검사 후 회사·공고 분석을 병렬 실행하고, 모두 끝나면 최종 검토를 실행한다.
- [x] 선택 모듈 실패가 있어도 최종 검토를 실행하고 `partial`을 반환한다.
- [x] 최종 검토 실패는 `failed`와 빈 결과를 반환한다.

## P2-06 실행 수명 주기

- [x] 취소 요청 이후 후속 노드를 실행하지 않고 `cancelled`로 종료한다.
- [x] SSE는 고정 진행 상태와 종료 이벤트만 보낸다.
- [x] 최종 재실행은 저장된 선행 결과를 재사용한다.
- [x] 특정 모듈 재실행은 해당 결과·오류를 교체하고 최종 검토를 다시 실행한다.

## P2-07 API

- [x] Page/Flow 시작 요청이 실행 ID를 반환한다.
- [x] 존재하지 않는 실행, 완료 전 결과 조회, 잘못된 재실행 모듈을 안전하게 거부한다.
- [x] 취소 API가 멱등적으로 취소 요청을 기록한다.

## P2-08 인수·평가

- [x] 성공·부분 실패·전체 실패·취소 응답이 동일한 최종 계약을 통과한다.
- [x] 실제 모델 평가는 기본 테스트에서 실행되지 않는다.
- [x] 실제 평가 시 스키마, 위치, 사실성, 필수 원칙 탐지를 검사한다.


## 2026-09-10 저장 계약 후속 변경 — 완료

- 완료 검토의 입력·모듈 결과·최종 응답을 JSON ReviewRecord로 저장한다.
- IndexedDB에서 조회한 기록을 재실행 API에 전달하며 이전 서버 실행에 의존하지 않는다.
- 저장 성공 후 서버 기록을 해제하고 실패 시 기록과 실행 ID를 유지한다.
- 서버 재시작 후 복원·재실행과 잘못된 기록 거부를 자동 검증한다.
